# Reporting map

Use the reporting framework that matches the work; confirm the current official checklist and conference rules before submission.

| Work | Starting framework | Focus |
|---|---|---|
| Randomized pilot/feasibility study | CONSORT extension for pilot and feasibility trials | feasibility objectives, progression criteria, participant flow, harms |
| Observational small study | STROBE | selection, variables, bias, confounding, missingness |
| Diagnostic or prototype performance study | STARD, when applicable | index test, reference standard, flow, accuracy uncertainty |
| Usability / human-factors study | Task-appropriate human-factors reporting | users, use scenarios, tasks, observed use errors, mitigations |
| Device clinical investigation | Applicable local requirements plus protocol | intended use, risk controls, endpoints, deviations, safety oversight |
| Conference abstract | Meeting-specific author instructions | word limits, structured headings, anonymity, disclosures |

## Device evidence ladder

State the strongest level actually supported:

1. Bench verification — technical measurements under defined conditions.
2. Simulated-use evaluation — representative users and scenarios without clinical-performance claims.
3. Usability/human-factors evaluation — task success, use errors, workload, and mitigation evidence.
4. Feasibility study — practicality, workflow, recruitment, implementation, or preliminary outcome signals.
5. Clinical performance study — only with study-specific clinical evidence and appropriate oversight.

Do not use evidence from one level to claim a higher level.
